# BUG-029 | Severidade: Baixa | Prioridade: P4 | Status: ABERTO (flake de teste; NÃO é defeito do produto)

**Fixture `ensureCategory` gera nome de categoria que pode colidir entre arquivos de teste em paralelo (`categories_level_name_uq`)**

Ambiente: tip `036e791`, clone limpo, `pnpm --filter @webag/api test:e2e` (108 arquivos, execução completa), 4 vCPU, com scripts de reteste rodando ao mesmo tempo.
Passos: rodar o e2e completo da API.
Esperado: 874 de 874.
Obtido: **873 de 874**. `test/discovery.e2e-spec.ts > categorias disponíveis só com loja visível no ponto (WB-011 C4)` falhou em `ensureCategory` (`test/helpers/fixtures.ts:294`): `duplicate key value violates unique constraint "categories_level_name_uq"` para o nome `Cat 57276-2`. O nome é `Cat ${Date.now() % 100000}-${categorySeq}`; `categorySeq` é uma variável de módulo (cada arquivo de teste roda num worker com a sua), então dois arquivos que chamam a fixture no mesmo milissegundo (módulo 100000) com o mesmo contador geram o mesmo nome.
**Reproduzido isolado: NÃO** (o arquivo sozinho passa, 11 de 11): é uma corrida rara, não um defeito do produto. A causa é visível no erro, por isso registro. Frequência neste reteste: 1 em 1 execução completa (nas 3 execuções do RC não apareceu).
Correção sugerida (backend-dev): trocar o sufixo por `randomUUID().slice(0, 8)` (o nome tem limite de 30 caracteres).
Evidência: `docs/qa/retestes/resultados/tip-e2e-api.txt`; arquivo isolado: 11 de 11 na mesma sessão.
História relacionada: WB-011 (fixture), DT de testes.
