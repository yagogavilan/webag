# BUG-030 | Severidade: Baixa | Prioridade: P4 | Status: ABERTO (teste não repetível; NÃO é defeito do produto)

**O spec `e2e-real/04-pedido-entrega-troca` consome o pedido de demonstração `WB-DM002`; a 2ª execução no mesmo banco falha**

Ambiente: tip `036e791`, clone limpo, API real, `pnpm web:e2e real` (ou `all`) duas vezes sem refazer o banco.
Passos: 1. `pnpm run setup`, API no ar. 2. `pnpm web:e2e real` (passa, 9 de 9). 3. Repetir `pnpm web:e2e real` sem `pnpm db:seed`/banco novo.
Esperado: a suíte de regressão do painel é repetível, ou o README diz que precisa de banco novo.
Obtido: na 2ª execução `04-pedido-entrega-troca.e2e.ts:34` falha com `Expected: "received", Received: "delivered"`: o teste escolhe o pedido do seed `WB-DM002` e espera o estado `received`; a 1ª execução já o levou a `delivered`. Os specs 07 e 08 do mesmo arquivo e os de captura ficam "did not run". Reproduzido (determinístico).
Impacto: só quem repete a suíte real no mesmo ambiente (CI com banco novo não é afetado). Não é falha do produto.
Correção sugerida (backend-dev/mobile-dev): o spec cria o seu próprio pedido pela API (como `troca-app-web.mjs`) em vez de depender de um pedido do seed, ou o README e o cabeçalho do spec dizem "uma execução por banco".
Evidência: `docs/qa/retestes/resultados/tip-web-e2e-all-mesma-porta.txt` (a 1ª execução da suíte real, em `tip-web-e2e-real.txt`, passou 9 de 9).
História relacionada: DT-065/066.
