# BUG-041 | Severidade: Crítica | Prioridade: P1 | Status: CORRIGIDO (aguarda reteste do QA)

**No build de produção do web, a ficha 360 (`/admin/lojas/{id}`) e o "Ver como" (`/admin/lojas/{id}/ver-como`) não abrem: "This page couldn't load" (erro do servidor); a aprovação de loja do admin (v1.0) também parou**

Ambiente: commit `8019b0c` (cópia limpa), `next build` + `next start` (Next 16.4.6, Turbopack), API falsa de `apps/web/e2e/fake-api`, Chromium 153 (`/opt/pw-browsers/chromium-1243`), Desktop Chrome 1280 px, login `admin@webag.local` e `operacao@webag.local`.
Passos: 1. `pnpm build` e `next start` em `apps/web`. 2. Entrar como admin. 3. Abrir `/admin/lojas/<id de uma loja>` (direto ou pelo link "Analisar a mais antiga" / linha da lista). 4. Repetir em `/admin/lojas/<id>/ver-como`.
Esperado: ficha 360 (WB-350), edição e pausa (WB-351), "Ver como" (WB-352) e a análise de cadastro (WB-103).
Obtido: tela "This page couldn’t load / A server error occurred. Reload to try again." e, no log do servidor: `Error: Attempted to call isStoreTab() from the server but isStoreTab is on the client` (e o mesmo com `isViewAsTab()`). Causa: `app/admin/(painel)/lojas/[id]/page.tsx:3,10` importa `isStoreTab` de `src/features/stores/store-detail.tsx` e `app/admin/(painel)/lojas/[id]/ver-como/page.tsx:2,11` importa `isViewAsTab` de `src/features/view-as/view-as-page.tsx`; os dois módulos começam com `'use client'`, então a função exportada vira referência de cliente e não pode ser chamada em página de servidor. Reproduzido 3 vezes (a bateria Playwright do admin e 2 execuções do caso novo).
Frequência: 100% nas duas rotas; nenhum perfil escapa (é renderização no servidor).
Impacto: toda a tela de R1.1 do admin fica inacessível (ficha, edição de dados, pausa, histórico, "Ver como"), e a análise e aprovação de loja pela interface (WB-103, v1.0) deixa de funcionar: regressão. Sem perda de dinheiro nem de dado. Contorno: só pela API; o fundador não tem como cadastrar loja pela interface.
Por que escapou: os testes de componente (jsdom, `store-ficha.spec`, `view-as.spec`) montam o componente sem a página de servidor; o CI não roda o Playwright (`ci.yml` não tem `test:e2e`); a revisão de segurança do front (§18.1) não rodou navegador; `pnpm build` não acusa porque o erro é de execução.
Sugestão: mover `isStoreTab` e `isViewAsTab` (e os tipos de aba) para um módulo sem `'use client'` (ex.: `store-tabs.ts`) importado pela página e pelo componente; manter os 2 casos de `apps/web/e2e/qa-r11-ficha-e-ver-como.e2e.ts` (hoje `test.fail`) como regressão; incluir o Playwright do admin no CI (ou um `next build` + `next start` com uma requisição por rota de servidor). Varredura que fiz: só estas 2 páginas importam função de módulo client (a 3ª, `excluir-conta/page.tsx` importa `hoursText` de `legal-copy.ts`, que não é client).
Efeito colateral no teste existente: `e2e/admin-aprovacao.e2e.ts` falha em 3 de 3 casos (o 1º, além disso, espera o `h1` "Fila de aprovação", que virou "Lojas" com abas na WB-350: seletor desatualizado).
Evidência: `docs/qa/relatorios/r1-1-r1-2-2026-11-22.md` §2 e §4; `docs/qa/performance/resultados/qa-r1-playwright-admin.txt` (62 passaram, 3 falharam, 3 ignorados); `apps/web/e2e/qa-r11-ficha-e-ver-como.e2e.ts`.
História relacionada: WB-350, WB-351, WB-352 (front); regressão de WB-103/104.

## Correção (mobile-dev, 2026-11-22)
- Causa raiz como descrita: `isStoreTab` e `isViewAsTab` movidos para `apps/web/src/features/stores/store-tabs.ts` e `apps/web/src/features/view-as/view-as-tabs.ts` (sem `'use client'`), importados pela página e pelo componente.
- Trava: `apps/web/src/server-client-boundary.spec.ts` (Vitest, roda no CI) falha se qualquer arquivo de `app/` ou `src/` sem `'use client'` importar de módulo `'use client'` algo que não seja componente (PascalCase) ou tipo, inclusive por barril. Conferido: com o código antigo ela acusa `isViewAsTab`. Varredura de todo o web: só havia estas 2 ocorrências.
- Prova (Chromium 153 existente, `next build` de produção + `next start`, API falsa): `admin-aprovacao` 3/3 e `qa-r11-ficha-e-ver-como` 2/2 passam (o `test.fail` virou `test`; o `h1` esperado agora é "Lojas"). Bateria inteira: 65 passaram, 3 ignorados, 2 falharam em `lojista-catalogo` (importação: "Caneca Esmaltada" não aparece nos rascunhos) e `lojista-produtos-mobile` (linha com 141 px > 100). Fora do escopo do BUG-041; a árvore tinha mudança em andamento de outro agente em `lojista-shell.tsx` (conflito de merge aberto depois), então não reexecutei para separar regressão de flakiness.
- Não resolvido: o CI continua sem `test:e2e` (sugestão do bug); a trava estática cobre a classe do erro sem build.
