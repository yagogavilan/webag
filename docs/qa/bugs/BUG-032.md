# BUG-032 | Severidade: Baixa | Prioridade: P4 | Status: CORRIGIDO (W0.2, mobile-dev, 2026-11-22; aguarda reteste do QA)

**`apps/web/src/features/admin-ops/alerts.spec.tsx` falha com o passar dos dias: usa data fixa e o relógio real avança**

Ambiente: Vitest do web. Esperado: o indicador "Mais antigo" mostra "2 dias" (alerta de 2026-11-17 contra "agora" de 2026-11-19). Obtido: "4 dias" (depois "5 dias"...), porque o teste lia o relógio real. Teste frágil, não defeito do produto (registrado como ação A-12 do PM; `plano-v1-1.md` §W0.2).

## Correção (mobile-dev, 2026-11-22)
- `alerts.spec.tsx`: `vi.useFakeTimers({ toFake: ['Date'], now: 2026-11-19T15:00Z })` em `beforeEach` e `vi.useRealTimers()` em `afterEach`. Só o `Date` é simulado, para os temporizadores do React Query e do `waitFor` seguirem reais.
- **Varredura:** rodei o Vitest completo (83 arquivos, 684 testes) e o Jest do mobile (48 suítes, 449 testes) com o relógio deslocado por um setup temporário (apagado) para 2026-11-22, 2026-11-20 e 2027-03-01.
- **Antes:** web com 1 falha (`alerts.spec.tsx`, "5 dias" em vez de "2 dias" em 2026-11-22); mobile 0 falhas.
- **Depois:** web 684/684 e mobile 449/449 nas 3 datas. Nenhum outro spec depende do "agora". Nada de código de produção alterado.
