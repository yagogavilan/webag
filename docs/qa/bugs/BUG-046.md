# BUG-046 | Severidade: Baixa | Prioridade: P3 | Status: ABERTO

**Playwright do lojista: o teste "importa uma planilha ... e abre os rascunhos" falha desde o front do cadastro rápido porque a API falsa não implementa `/product-drafts` nem `/catalog/quick-start`**

Ambiente: commit `4d25e5f` x `a6953da`, `next build` + `next start`, API falsa `apps/web/e2e/fake-api/server.mjs`, Chromium 153.
Passos: `pnpm exec playwright test e2e/lojista-catalogo.e2e.ts` (2º caso).
Esperado: passar como na v1.0 (`a6953da`: 3 de 3 passam, medido).
Obtido: falha em `lojista-catalogo.e2e.ts:91` (`getByText('Caneca Esmaltada')` não aparece). A tela "Rascunhos" (`DraftsPanel`, WB-371) agora lê `GET .../product-drafts` e `GET .../catalog/quick-start`; a API falsa não tem essas rotas (nenhuma ocorrência de `product-drafts` no `server.mjs`), a tela mostra "Não conseguimos carregar agora" (contexto de erro do Playwright). O 1º caso do arquivo foi atualizado para `/novo/completo`; este não.
É falha do TESTE/infra, não do produto: os caminhos e a forma que o front usa (`lib/api/catalog.ts`) batem com as rotas reais da API (cobertas pelos e2e `r12-drafts`). Mas **nenhum teste ligava o painel de rascunhos à API real ou a uma API falsa**, só componente com mock.
Impacto: a suíte Playwright do lojista fica vermelha; como o CI não roda Playwright, ninguém vê (mesma lacuna do BUG-041).
Sugestão: implementar `product-drafts` (GET/POST, lista paginada) e `catalog/quick-start` na API falsa e ajustar o caso; incluir o Playwright do admin e do lojista no CI ou num job noturno.
Evidência: `docs/qa/relatorios/r1-1-r1-2-2026-11-22.md` (apêndice Reteste).
História relacionada: WB-371, WB-065 (importação), BUG-041 (lacuna do CI).
