# BUG-027 | Severidade: Baixa | Prioridade: P4 | Status: ABERTO

**Listas do admin aceitam `limit` fora do contrato em vez de recusar (400)**

Ambiente: API do RC (`f622bc9`), perfil super admin, provedor `fake`.
Passos: `GET /v1/admin/alerts?limit=0`, `limit=999`, `limit=abc`; `GET /v1/admin/orders?limit=51`, `limit=0`, `limit=abc`.
Esperado (OpenAPI, parâmetro `Limit`: inteiro, mínimo 1, máximo 50): 400 `VALIDATION_FAILED` para valor fora da faixa ou não numérico.
Obtido: sempre 200; o valor é ajustado em silêncio (`limit=0` devolve a página padrão de 20; `999` e `51` devolvem 50; `abc` devolve a página padrão). Nenhum 5xx, nenhuma página maior que 50, sem vazamento.
Impacto: nenhum para o usuário; só diverge do contrato e do que um teste de contrato espera. Decisão do tech-lead: ou o OpenAPI passa a dizer "ajustado para 1 a 50", ou o `parseLimit` recusa. Os mesmos filtros inválidos (`status`, `area`, `severity`, `kind`, `mode`, UUID, data, cursor adulterado) JÁ dão 400.
Evidência: `docs/qa/retestes/resultados/rc-alertas.txt` (B3-f-limit) e `rc-pedidos.txt` (B5-f-limit).
História relacionada: WB-198, WB-108 (B3, B5).
