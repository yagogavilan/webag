# BUG-050 | Severidade: Baixa | Prioridade: P3 | Status: ABERTO

**"Preços e estoque": com 201 produtos selecionados, o diálogo do reajuste diz só "Não foi possível calcular a prévia" e não explica o teto de 200**

Ambiente: commit `57788f3`, `next build` + `next start`, Chrome 1280 x 720 (build de produção do Playwright do QA), API falsa com a resposta REAL do contrato injetada (`422 BULK_TOO_LARGE`, `errors[0].message = "No máximo 200 produtos por vez."`), 3 execuções do caso. Na API real o 422 vem de `bulk` do lojista desde o A3 do review R1.3 (antes era 400 genérico).
Passos: 1. Entrar como lojista com 205 produtos ativos. 2. Abrir `/lojista/produtos/precos`. 3. Marcar "Selecionar todos os 200 da lista" e marcar mais 1 produto (201 selecionados). 4. "Mudar preço", digitar 10.
Esperado: o lojista sabe que o limite é 200 e o que fazer ("Desmarque 1 produto"); sem opção de tentar de novo que nunca vai funcionar.
Obtido: a tela mostra o aviso "O máximo é 200 produtos por vez. Desmarque alguns." **atrás** do diálogo; dentro dele, o texto "Não foi possível calcular a prévia. Tentar de novo" e o botão "Aumentar preço de 201 produtos" **desabilitado** (correto). "Tentar de novo" falha sempre com o mesmo 422. `catalogErrorMessage` (`apps/web/src/lib/api/catalog.ts:103-150`) não tem o caso `BULK_TOO_LARGE`, e a barra de ações abre o diálogo mesmo acima do teto.
Impacto: baixo. Nada é aplicado (o botão não habilita) e o aviso de 200 está na página; mas quem abre o diálogo fica sem o porquê e com um "Tentar de novo" inútil. A seleção acima de 200 exige marcar um item além do "Selecionar todos" (que já limita a 200), por isso é rara. Sem perda de dado ou dinheiro.
Causa: UX; o código novo `BULK_TOO_LARGE` (DEC-135 item 2) entrou na API e no contrato, mas não no mapa de mensagens do web nem na barra (`BulkBar` não desabilita "Mudar preço" acima de `BULK_MAX`). Teste ausente (`bulk-bar.spec.tsx` e `price-table.spec.tsx` não cobrem 201).
Sugestão: desabilitar "Mudar preço" e "Pausar" na barra quando `count > BULK_MAX`, com o motivo escrito ao lado; e mapear `BULK_TOO_LARGE` em `catalogErrorMessage` ("Selecione no máximo 200 produtos por vez."). O mesmo vale para a lista de produtos (`products-page.tsx:219`).
Evidência: `apps/web/e2e/qa-r13-reajuste.e2e.ts`, caso F2 (marcado `test.fail` com este BUG; falha de propósito até a correção, e então a linha `test.fail` sai); texto do diálogo registrado em `qa-r13-notes.log`.
História relacionada: WB-377 C9 (limite de 200, "Selecionar todos" com a contagem), WB-353 C6.
