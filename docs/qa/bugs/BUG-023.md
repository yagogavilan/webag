# BUG-023 | Severidade: Baixa | Prioridade: P3 | Status: FECHADO em 2026-11-19 (reteste G4 final)

**O cupom de demonstração BEMVINDO10 do seed é de primeira compra e não tem teto de usos, contra a regra que o próprio admin impõe (SEC-170d, DEC-056)**

Ambiente: seed completo (`pnpm run setup`), API HEAD `b550088`.
Passos: `select code, first_purchase_only, max_uses from coupons where code = 'BEMVINDO10'` -> `t` e nulo. O admin recusa criar (400 `maxUses`: "Cupom de primeira compra precisa de teto...") e recusa remover o teto depois (PATCH `maxUses: null`, 400); verificado em SEC-170d a 170f.
Esperado: o dado de demonstração obedece à regra (ex.: `max_uses` = 100).
Obtido: seed sem teto; documentado no README como cupom de demonstração. Se alguém copiar o seed para produção, a campanha de primeira compra fica sem teto de orçamento (a proteção que sustenta a liberação do SEC-155).
Impacto: baixo (dev). Correção de uma linha em `apps/api/seed/onda3.ts`. História relacionada: SEC-155, SEC-170, DEC-056.

**Reteste G4 final (2026-11-19, QA, commit congelado 0d902ab; saídas em `docs/qa/retestes/resultados/g4-*.txt`):** `BEMVINDO10` no banco semeado do zero tem `max_uses = 100` e nenhum cupom da plataforma ativo está sem teto (`onda-8.mjs bugs`, BUG-023a/b). Todo cupom da plataforma novo exige `maxUses` (`onda-8.mjs cupom`, 14 de 14: percentual, fixo e frete grátis sem teto ou com 0 = 400; PATCH `maxUses: null` = 400; com teto = 201; detalhe traz `maxCost` e `usesByStore`).
